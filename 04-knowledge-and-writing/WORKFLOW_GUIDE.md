# 知识沉淀与内容输出工作流说明

## 5. 工作流四：知识沉淀与内容输出

### 适用场景

当你已经完成调研、学习、拆解、面试复盘或文章素材整理，需要把结果沉淀到长期知识库，或者转化成可发布文章时，使用这条链路。

推荐顺序：

```text
obsidian-knowledge-saver
  -> simin-article-cowriter
  -> obsidian-knowledge-saver
```

也可以在任何工作流结束后直接调用 `obsidian-knowledge-saver`。

### 5.1 obsidian-knowledge-saver：Obsidian 原子知识库

**它解决什么问题**

很多对话和学习成果聊完就散了。`obsidian-knowledge-saver` 用来把对话、素材、文章、会议记录、学习笔记拆成原子知识点，写入 Obsidian，并维护索引和日志。

**典型触发语**

- “帮我沉淀到知识库。”
- “把这个整理成笔记。”
- “写入 Obsidian。”
- “帮我消化这篇文章。”
- “lint 一下知识库。”

**四种模式**

1. Init：初始化知识库。
2. Save：把当前对话沉淀为知识点。
3. Ingest：消化文章、文档、素材。
4. Lint：知识库健康检查。

**知识库五层结构**

- 信息源：原始素材，只读不改。
- 原子笔记：每条只表达一个知识点。
- 输出文档：文章、PPT、报告等成品。
- 索引：自动维护导航。
- 日志：记录所有操作。

**Save 流程**

1. 读取配置。
2. 回顾对话，识别值得保存的知识点。
3. 拆分为原子笔记。
4. 检查是否已有相同或相近笔记。
5. 生成笔记内容。
6. 展示给用户确认。
7. 写入 vault。
8. 更新索引和日志。

**Ingest 流程**

1. 获取素材。
2. 阅读并讨论。
3. 提炼原子笔记。
4. 存档原始素材。
5. 复用 Save 的写入流程。

**Lint 流程**

检查内容包括：

- 笔记是否过长。
- 是否一篇笔记包含多个知识点。
- 是否缺少链接。
- 是否存在重复主题。
- 是否索引失效。
- 是否日志缺失。

**产出**

- 原子笔记。
- 知识库索引更新。
- 操作日志。
- 健康检查报告。

### 5.2 simin-article-cowriter：思敏长文共创

**它解决什么问题**

用于把 AI、产品、Agent、RAG、产品拆解等素材写成可发布长文。它不是一次性代写，而是分阶段共创，保留作者判断。

**典型触发语**

- “我想写一篇关于 AI Agent 的文章。”
- “帮我理一下这篇文章思路。”
- “这个话题可以写成长文吗？”
- “帮我把这些素材整理成文章。”

**核心原则**

- 共创，不代写。
- 先确认选题和观点，再写大纲。
- 每章逐段推进，不一次性输出全文。
- 强调观点独特、有干货、看得懂、能带走东西。
- 避免 AI 味表达。

**写作风格**

- 场景锚定：用一个真实场景贯穿全文。
- 问题推导：先提出问题，再一步步排除错误解法。
- 逐层拆解：从是什么、为什么、怎么做、案例、进阶展开。
- 类比降维：用生活化例子解释技术概念。
- 短段落、清晰小标题、表格和引用块辅助阅读。

**执行过程**

1. 阶段零：理解意图。
2. 阶段一：选题与定位。
3. 阶段二：大纲设计。
4. 阶段三：逐章节共创。
5. 阶段四：全文审查。
6. 阶段五：输出到 Obsidian。

**可输出内容**

- 文章选题分析。
- 核心观点。
- 文章大纲。
- 逐章节正文。
- 全文审查意见。
- 可发布 Markdown。
- 需要时可规划 Excalidraw 图表。
