# 能力建设与入职加速工作流说明

## 4. 工作流三：能力建设与入职加速

### 适用场景

当你需要快速进入一个陌生 AI 领域、拆解目标公司产品、为面试或入职建立认知体系时，使用这条链路。

推荐顺序：

```text
48h-accelerated-learning
  -> interactive-learning
  -> ai-product-teardown
  -> obsidian-knowledge-saver
```

### 4.1 48h-accelerated-learning：48 小时领域速成

**它解决什么问题**

用于快速搞懂一个陌生领域，先建立认知骨架，而不是陷入碎片知识。它适合面试前、转岗前、接手新项目前使用。

**典型触发语**

- “帮我 48 小时搞懂多模态。”
- “我需要快速了解 Agent 评测。”
- “两天内帮我建立 RAG 的认知框架。”

**信息源架构**

- 第一层：Claude 自身知识，零门槛立即可用。
- 第二层：Web Search，补充实时信息。
- 第三层：NotebookLM，可选增强，用于查询用户已上传资料。

**三个 Phase**

1. Phase 1：领域全景扫描。
   - 目标是回答这个领域最重要的心智模型是什么。
   - 输出 5 个核心心智模型。
   - 找出 3 个争议地带。
   - 给出推荐资料和学习路线。
2. Phase 2：深度攻坚。
   - 选出最关键、最卡人的问题深入拆。
   - 不是泛泛讲概念，而是解释专家如何思考。
   - 适合攻克 “RAG 为什么会 hallucinate” “Agent 评测到底评什么” 这类问题。
3. Phase 3：知识串联与总结。
   - 形成自己的学习笔记。
   - 记录顿悟时刻、踩坑、未完全理解的问题。
   - 输出后续学习建议。

**产出**

- 48 小时学习笔记。
- 领域整体理解。
- 5 个核心心智模型。
- 3 个争议地带。
- 深度问题拆解。
- 推荐资料。
- 后续学习路线。

### 4.2 interactive-learning：一对一自适应学习

**它解决什么问题**

如果 `48h-accelerated-learning` 是建立地图，`interactive-learning` 就是按地图逐课学习。它基于掌握学习和苏格拉底式提问，不是一次性讲完，而是边学边检查理解。

**典型触发语**

- “我想系统学 RAG。”
- “帮我理解 Agent。”
- “这个概念我不太懂。”
- “教我 AI 产品评测体系。”

**执行过程**

1. 判断当前环境是否能写文件。
2. 如果能写文件，会创建学习文件夹：
   - `进度.md`
   - `01_{第一课标题}.md`
3. 先设计知识图谱：
   - 核心概念。
   - 概念依赖关系。
   - 前置知识。
4. 用 1-2 个具体问题判断用户起点。
5. 规划学习阶梯。
6. 每课聚焦一个核心概念。
7. 通过思考题和追问判断掌握程度。
8. 只有理解当前内容后，才推进下一课。

**产出**

- 学习路径。
- 分课笔记。
- 进度追踪。
- 误区记录。
- 阶段回顾。
- 学习总结文档。

**适合搭配**

- 前置用 `48h-accelerated-learning` 找到知识地图。
- 学完后用 `obsidian-knowledge-saver` 沉淀成原子笔记。

### 4.3 ai-product-teardown：AI 产品逆向拆解

**它解决什么问题**

用于系统拆解一个 AI 产品或竞品，适合面试前研究目标公司、入职后理解竞品、做产品复刻或技术方案推导。

**典型触发语**

- “帮我拆解一下 Cursor。”
- “分析一下 Kimi 的产品架构。”
- “这个 AI 产品怎么做的？”
- “面试要聊某个产品，帮我准备。”

**六层框架**

1. 市场层：目标市场、机会、增长背景。
2. 商业层：商业模式、获客、定价、可持续性。
3. 用户层：用户场景、核心任务、体验路径、评测维度。
4. 技术层：架构类型、Agent 组成、工具调用、上下文流转。
5. 模型层：模型选择、能力边界、成本和质量权衡。
6. 基础层：数据、工程基础设施、权限、安全和运维。

**执行过程**

1. Phase 0：初始化，搜索产品基本信息，确认拆解对象和目标。
2. Phase 1-2：市场层和商业层，搜索驱动。
3. Phase 2.5：生成评测维度。
4. Phase 3：用户层，要求用户亲自体验产品。
5. Phase 4：技术层，协作推导 Agent、上下文和提示词。
6. Phase 5-6：模型层和基础层，结合搜索和推导。
7. Phase 7：汇总成完整拆解。

**产出**

- 产品拆解项目文件夹。
- 概览文件。
- 市场层、商业层、用户层、技术层、模型层、基础层文档。
- 评测表。
- Agent 卡片。
- 上下文 Schema。
- 最终汇总。

**核心原则**

- 先自己梳理，再问 AI 对不对。
- 没有体验就不要轻易评价。
- 信息缺口要标出来，不假装知道。
- 技术推导要说明置信度。
